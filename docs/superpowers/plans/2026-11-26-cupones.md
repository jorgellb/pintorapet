# Cupones de descuento — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Discount coupons for the web shop, with many combinable rules, managed in Admin › Cupones, applied by the database when the checkout quote is priced.

**Architecture:** One migration adds `coupons`, `coupon_redemptions`, coupon columns on `checkout_quotes` and `orders`, a pure pricing function `coupon_price`, and wires it into `create_checkout_quote` (lines get the discounted unit price, so orders, Stripe/PayPal line items, invoices and refunds need no change). A use is claimed right after `reserve_checkout`, once the email is on the order, with the coupon row locked. TypeScript passes the code through the quote API and shows it in the checkout; Admin gets list + form pages.

**Tech Stack:** Astro 7 SSR, Aiven PostgreSQL (plpgsql, `SECURITY DEFINER`, RLS), zod, vitest, Playwright, Python SQL check scripts.

**Spec:** `docs/superpowers/specs/2026-11-26-cupones-design.md`

## Global Constraints

- Shop only: no coupon on commission payment, phone orders (`create_manual_order*`), market stall sales.
- One coupon per order. Code `^[A-Z0-9_-]{3,30}$`, stored upper-case; input trimmed and upper-cased.
- All coupon amounts (fixed, cap, minimum purchase) and the free-shipping threshold are measured on catalogue prices with VAT; for `no_vat` the VAT is taken off each discounted line afterwards.
- Free shipping is judged **after** the discount.
- Buy-X-get-Y and Nth-unit discounts are spread over the qualifying lines (never a 0 € unit just for being "the free one").
- Every unit keeps an integer price; rounding favours the customer. Total never below 50 cents; no unit below 0.
- A paid order is never blocked by a coupon problem (over-limit is flagged, not sent to review).
- Never edit applied migrations; new one is `supabase/migrations/20261126000009_coupons.sql`. Before replacing a function, check its production body equals the latest migration (`pg_get_functiondef`, as done for 0008).
- Web copy in ES and EN. Admin copy in Spanish. Code comments in English.
- Tests: no real emails (`EMAIL_ADMIN=delivered@resend.dev`), no real invoices, local Docker DB for e2e; throwaway specs `e2e/zz-*.spec.ts` deleted afterwards.
- Commit and push only when Jorge says so: the "Commit" steps below are checkpoints (tests green, `git diff` reviewed); the actual commit and push happen once, at the end, after he approves.

## Review Focus

- A coupon paused/expired/used up between applying it and paying → the checkout says why and re-prices without it; nothing is charged at the old price. (Task 3 `claim refuses a coupon paused after the quote`; Task 6 e2e.)
- Two tabs taking the last use at once → the coupon row lock lets only one through. (Task 3 `the last use goes to one order only`.)
- Cart edited after applying (qualifying piece removed, total under the minimum) → re-quote shows the reason, not a stale discount. (Task 2 `removing the only taza drops the discount with COUPON_NO_ITEMS`.)
- Fixed amount bigger than the order / 100 % coupon → total ≥ 50 cents, units ≥ 0, Stripe accepts the session. (Task 1 `a 50 € coupon on a 9,99 € order leaves 0,50 €`.)
- Code typed in lower case or with spaces, or a pickup order with a free-shipping coupon → normalised / clear reason. (Task 1 `' navidad10 ' finds NAVIDAD10`; Task 2 `free-shipping coupon on pickup gives COUPON_PICKUP`.)

  - table `public.coupons`: `id uuid pk`, `code text unique` (check regex), `note text default ''`, `status coupon_status default 'active'`, `kind coupon_kind`, `percent numeric(5,2)` (1–100; `percent`, `nth_unit`), `amount_cents int` (`fixed`), `cap_cents int` (max discount for `percent`; max shipping covered for `free_shipping`), `buy_qty int`, `get_qty int` (`buy_x_get_y`), `nth int ≥ 2` (`nth_unit`), `category_ids uuid[]`, `collection_ids uuid[]`, `product_ids uuid[]`, `excluded_product_ids uuid[]` (all default `'{}'`; empty targets = whole shop), `min_subtotal_cents int`, `min_units int`, `zone_ids uuid[] default '{}'`, `allow_shipping bool default true`, `allow_pickup bool default true`, `first_order_only bool default false`, `require_account bool default false`, `emails text[] default '{}'` (lower-case), `emails_require_account bool default false`, `starts_at timestamptz`, `ends_at timestamptz`, `weekdays smallint[] default '{}'` (ISO 1 = Monday … 7), `max_uses int`, `max_uses_per_customer int`, `announce bool default false`, `version int default 1`, `created_at`, `updated_at`.   - table `public.coupon_redemptions`: `coupon_id uuid references coupons on delete restrict`, `order_id uuid unique references orders on delete cascade`, `email text`, `customer_id uuid`, `discount_cents int`, `created_at`.
  - `orders` + `coupon_id uuid references coupons on delete set null`, `coupon_code text`, `coupon_discount_cents int not null default 0`, `coupon_over_limit bool not null default false`.
  - `checkout_quotes` + `coupon_id uuid`, `coupon_code text`, `coupon_discount_cents int not null default 0`, `coupon_error text`, `coupon_missing_cents int`.
  - RLS: `coupons` and `coupon_redemptions` readable and writable only by `is_admin()` (authenticated); no anon grant.
  - `public.coupon_uses(p_coupon_id uuid, p_email text, p_customer_id uuid, p_except_order uuid) returns table(total int, by_customer int)` — redemptions whose order is not `expired`/`cancelled`, excluding `p_except_order`; `by_customer` matches `lower(email)` or `customer_id`.
  - `public.coupon_price(p_code text, p_lines jsonb, p_ctx jsonb) returns jsonb`, `STABLE SECURITY DEFINER`, service_role only.
    - `p_lines`: `[{product_id, quantity, gross_cents}]` (catalogue unit price with VAT).
    - `p_ctx`: `{zone_id, pickup bool, shipping_cents (charged), email, customer_id, order_id, at}` — any may be null; `at` defaults to `now()`.
    - Ok: `{ok: true, coupon_id, code, version, kind, discount_cents, shipping_free bool, shipping_cap_cents, lines: [{product_id, unit_gross_cents}]}` (lines in input order, every input line present).
    - Not ok: `{ok: false, code, reason, missing_cents?, missing_units?}`, `reason` ∈ `COUPON_NOT_FOUND` (unknown, paused or archived), `COUPON_NOT_STARTED`, `COUPON_EXPIRED`, `COUPON_WRONG_DAY`, `COUPON_NO_ITEMS`, `COUPON_MIN_SUBTOTAL`, `COUPON_MIN_UNITS`, `COUPON_ZONE`, `COUPON_PICKUP`, `COUPON_SHIPPING`, `COUPON_FIRST_ORDER`, `COUPON_ACCOUNT`, `COUPON_EMAIL`, `COUPON_USED`, `COUPON_SOLD_OUT`.
    - Checks in this order: found+active → dates (Europe/Madrid) → weekday → shipping/pickup/zone → qualifying lines exist → minimums (on qualifying gross) → who (`first_order_only`: any order with that email/customer and `paid_at is not null`; `require_account`: `customer_id` present; `emails`: `lower(email)` in list, and if `emails_require_account` the email must be the signed-in account's — `auth.users.email` of `customer_id`) — who-rules skipped when both email and customer_id are null, except `require_account` → uses (`max_uses` → `COUPON_SOLD_OUT`; per customer → `COUPON_USED`).
    - Qualifying: product not in `excluded_product_ids` and (all targets empty, or product in `product_ids`, or its `category_id` in `category_ids`, or its `collection_id` in `collection_ids`).
- Allocation (not determined by the signature):
  - `D` (gross cents off the qualifying pieces): `percent` → Σ round(unit × p/100) per unit, then `least(D, cap)`; `fixed` → `amount_cents`; `buy_x_get_y` → sum of the `get_qty × floor(n/(buy+get))` cheapest qualifying units; `nth_unit` → Σ round(price × p/100) over the `floor(n/nth)` cheapest units; `free_shipping` → 0 (`shipping_free`, cap).
  - `D := least(D, Σ qualifying gross, Σ all gross + shipping_cents − 50)` (≥ 0).
  - Spread `D` over qualifying lines proportionally to line gross (floor), leftover cents to the largest line; per line, per-unit cut = ceil(line share / quantity), never above the unit price. Reported `discount_cents` = Σ (gross − unit_gross) × qty (may exceed `D` by under `quantity` cents).
